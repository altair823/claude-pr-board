# pr-board

Claude Code 패널에 현재 저장소의 열린 PR과 브랜치별 CI 상태를 보여 주는 mod입니다. CI가 오래 걸리거나 러너가 바빠 기다릴 때, 대화를 이어 가면서 어디까지 진행됐는지 볼 수 있습니다.

GitHub(GitHub Enterprise 포함)와 Gitea 저장소를 지원합니다.

## 설치

```
claude plugin marketplace add altair823/claude-pr-board
claude plugin install pr-board@claude-pr-board
```

저장소에 따라 다음 CLI 가운데 하나가 필요합니다. mod는 이 CLI로 조회만 하고 토큰을 따로 다루지 않습니다.

- GitHub: [gh](https://cli.github.com)로 로그인해 둡니다(`gh auth login`). GitHub Enterprise는 `gh auth login --hostname <호스트>`로 그 호스트에 로그인해 두면 GitHub로 인식합니다.
- Gitea: [tea](https://gitea.com/gitea/tea)로 저장소의 Gitea에 로그인해 둡니다(`tea login add`).

mod는 origin 원격의 호스트를 보고 둘 가운데 하나를 고릅니다. github.com이거나 gh로 로그인한 호스트면 GitHub, 아니면 Gitea로 봅니다.

`/pr-board`로 패널을 엽니다. 직접 닫지 않으면 다음 세션에도 열립니다. 다만 git 저장소가 아니거나 origin 원격이 없는 디렉터리에서는 자동으로 열지 않습니다. 이런 곳에서 `/pr-board`로 열면 이유만 보여 줍니다. git-graph 같은 다른 패널과 함께 쓰면 패널 위쪽의 탭을 클릭해 바꿉니다.

## 화면

패널은 위에서부터 열린 PR 구역, PR이 없는 브랜치 구역, 커서가 있는 줄의 상세, 단축키로 나뉩니다. 구역 이름 옆의 숫자는 그 구역의 줄 수입니다.

| 표시 | 뜻 |
|---|---|
| `▶ #12  로그인 화면` | 열린 PR. 맨 앞 기호는 PR 끝 커밋에서 돈 CI의 상태입니다 |
| `◌ feat/queue  커밋 제목` | PR이 없는 브랜치. CI가 도는 중이거나 하루 안에 돈 브랜치만 나옵니다 |
| `●` | 지금 체크아웃한 브랜치 |
| `▶` 와 `test 3분` | 실행 중인 작업과 시작한 뒤 지난 시간 |
| `◌` 와 `대기 12분` | 러너를 기다리는 작업과 기다린 시간. 앞 작업이 끝나야 시작하는 작업은 앞 작업이 끝난 뒤부터 셉니다 |
| `✗` 와 `test 실패` | 실패한 작업 |
| `✓` 와 `5분 전` | 모든 작업이 성공한 뒤 지난 시간 |
| `승인`, `변경 요청`, `리뷰 대기` | 리뷰어마다 마지막 결정. Gitea에서는 새 커밋 전에 남긴 리뷰를 세지 않습니다. GitHub에서는 GitHub의 규칙대로 새 커밋 뒤에도 남습니다 |
| `열린 PR 30+` | 한 번에 읽는 PR 수(GitHub 30개, Gitea 50개)를 채웠다는 뜻입니다. 최근에 바뀐 PR부터 보여 줍니다 |

커서가 있는 줄은 배경색으로 표시하고, 그 줄의 상세가 아래에 나옵니다. PR이면 브랜치, 충돌 여부(Gitea만), 작성자, 리뷰어별 마지막 리뷰, 작업별 결과가 나옵니다. 작업이 한 줄에 다 들어가지 않으면 실패, 실행, 대기 중인 작업부터 보여 줍니다. GitHub의 PR은 GitHub Actions 작업뿐 아니라 PR 끝 커밋에 결과를 남긴 다른 CI도 함께 보여 줍니다. 앞 작업이 끝나기를 기다리는 작업은 러너 대기와 구분해 `◌ release  test 뒤`처럼 흐리게 보여 줍니다.

패널이 git-graph 같은 다른 탭에 가려져 있으면, 입력창 바로 위에 CI 요약 한 줄이 나옵니다. 지금 브랜치의 CI가 돌고 있거나 실패했으면 `● #12 ▶ test 3분    다른 줄 대기 1`처럼 지금 브랜치를 먼저 쓰고 나머지는 개수만 셉니다. 지금 브랜치에 보여 줄 것이 없으면 `CI ▶ #12 test 3분  ◌ feat/queue 대기 12분`처럼 도는 줄을 하나씩 씁니다. PR 탭이 보이는 동안에는 같은 내용이 패널에 있으므로 나오지 않습니다. 기다리던 CI가 끝나거나 새 리뷰 결과가 나오면 알림이 뜹니다. 패널을 닫으면 요약과 알림도 멈춥니다.

상태줄을 쓰지 않는 이유는 Claude Code가 mod의 상태줄 앞에 항상 `⚠ <mod 이름>:`을 붙여서, 정보성 내용도 경고처럼 보이기 때문입니다.

## 조작

패널의 줄을 클릭하거나 `ctrl+x tab`을 누르면 들어가고, `Esc`로 나옵니다.

| 키 | 동작 |
|---|---|
| `↑` `↓` | 줄 이동 |
| `1` | 리뷰 코멘트를 반영해 달라는 문장을 입력창에 넣기(PR 줄) |
| `2` | 실패한 CI를 고쳐 달라는 문장을 입력창에 넣기 |
| `3` | PR을 머지해 달라는 문장을 입력창에 넣기(PR 줄) |
| `r` | 지금 다시 읽기 |

커서가 있는 줄에서 쓸 수 없는 단축키는 흐리게 보입니다. 입력창에 넣기만 하고 보내지는 않습니다. 문장을 확인하고 직접 보내면 됩니다.

## 서버 부하

회사 GitHub Enterprise처럼 부하에 민감한 서버에서도 쓸 수 있도록 다음처럼 조회합니다.

- 패널을 연 세션에서만 조회합니다. 패널을 열지 않은 세션은 서버에 요청을 보내지 않습니다.
- 대기 중이거나 실행 중인 CI가 있으면 Gitea는 15초, GitHub는 30초마다 다시 읽습니다. 도는 CI가 없으면 5분마다 읽습니다.
- Claude가 `git push`, `tea` 명령, PR과 CI를 바꾸는 `gh` 명령(`gh pr create`, `gh pr merge`, `gh run rerun` 등)을 실행하면 바로 다시 읽습니다. `/cd`로 디렉터리를 바꿔도 바로 다시 읽습니다.
- 한 번 읽을 때 PR 목록과 CI 실행 목록을 요청합니다. 작업 목록은 목록에 보이는 실행만 요청합니다. 끝난 실행은 한 번만 읽고, 끝나지 않은 실행은 지금 브랜치와 커서가 있는 줄부터 세 개까지만 읽습니다. 나머지 줄은 실행 단위로 상태를 보여 줍니다.
- Gitea는 리뷰를 PR이 바뀌었을 때만 PR마다 요청합니다.
- GitHub는 PR 목록 하나(GraphQL)에 리뷰와 PR 끝 커밋의 작업 결과가 함께 오므로, PR마다 리뷰나 작업 목록을 묻지 않습니다. 이 요청에서 CI 결과 계산이 가장 무거워서 최근에 바뀐 PR 30개만 읽습니다. 충돌 여부는 묻지 않습니다. 물으면 GitHub가 PR마다 병합 가능 여부를 다시 계산하기 때문입니다.
- GitHub의 실행 목록은 브랜치 줄에 쓸 push 실행 30개만 받습니다. 실행마다 저장소 정보가 붙어 응답이 크기 때문입니다.

CI가 도는 동안 GitHub에 보내는 요청은 30초마다 GraphQL 1개와 REST 1~4개입니다. 시간당 요청 한도(사용자마다 5,000개)의 10% 정도입니다.
- 같은 저장소를 연 세션이 여러 개면 조회 결과를 `~/.cache/claude-pr-board/<호스트>/<저장소>.json`에 두고 함께 씁니다. 다른 세션이 읽은 결과가 아직 새것이면 서버에 묻지 않고 그 파일을 읽습니다. 그래서 세션이 몇 개든 저장소마다 한 세션분만 조회합니다. push 뒤나 `r`을 누를 때는 파일과 상관없이 서버에서 읽습니다.

두 세션의 조회 시각이 같은 순간에 돌아오면 드물게 둘 다 조회할 수 있습니다.

## 이슈와 PR

버그나 제안은 이슈로 올리면 됩니다.

이 저장소는 비공개 저장소를 그대로 옮겨 오는 미러라서, 여기서 PR을 머지하면 다음 동기화 때 지워집니다. 그래서 PR 내용은 비공개 저장소에 옮겨 반영하고, PR 작성자를 커밋의 공동 작성자로 남긴 뒤 PR을 닫습니다.

## 개발

```
claude plugin validate .
claude plugin test .
```

main에 push하면 CI가 시험을 돌리고, 통과하면 `release` 브랜치에 다음 버전을 올리고 태그를 붙입니다(`scripts/ci-release.sh`). 설치본은 `release` 브랜치만 받습니다.
